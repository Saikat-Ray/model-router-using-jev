Model router architecture

Jev decides which model handles each request. Your code owns the constraints, the policy, and the logs.

How a request flows

  1. Caller to Router. The router filters the registry by hard constraints (context length, vision), asks Jev to pick among what remains, then applies the confidence threshold.
  2. Router to Executor. The executor calls the chosen model through OpenRouter, falling back to stronger models, then weaker ones, if a call fails.
  3. Executor to Decision log. Every request writes one row with the pick, probabilities, latency, and cost.
  4. Log to Eval harness. Logged decisions and a labeled prompt set are used to tune the threshold.

Swap points

  1. Jev's endpoint lives behind a small Decider interface, so moving off OpenRouter means one new client class.
  2. The model APIs call is isolated in the executor, so direct provider APIs or a gateway can replace it independently.
